# 交互行为

[English](en/INTERACTIONS.md)

本文记录 MiniC 桌面层和收纳盒应保持的用户可见行为。实现细节改变时，这些结果仍应成立。

## 选择与编辑

- 双击以两次按下的系统时间与屏幕距离判定，在第二次有效松开时打开；拖动、未完成的点击、切换项目或点击空白区域会取消无效连续点击。
- 文件元数据刷新保留正在使用的图标对象、选择与编辑状态；重命名期间不隐藏整个桌面图标层，文件变化延后同步而不直接丢弃。
- 桌面和收纳盒项目按 Windows 双击时间与距离识别连续点击，不依赖桌面层激活前后的 WPF 点击计数；已进入拖动的手势不得触发打开。
- 单击选中一个图标时显示完整名称；取消选中或多选时恢复紧凑名称。
- 桌面和收纳盒空白区域支持框选，`Ctrl` 框选用于追加或反选。
- 点击其他桌面区域、收纳盒或普通应用时，清除不再有效的选择、菜单和编辑状态。
- `F2` 或重命名命令在名称位置原位编辑；默认只选中文件名主体，不选中可见扩展名。`Enter` 提交，`Escape` 取消，失焦取消文件名编辑。
- 重命名编辑器只替换图标下方的原名称，宽度不得超出文件名槽位，也不得横向撑开图标项或遮挡图标。
- 在重命名输入框内拖动选择文字时，鼠标事件只用于文本选择，不得移动文件图标。
- 双击收纳盒标题后在标题栏原位编辑；`Enter` 或失焦提交，`Escape` 取消。
- 文件名是否显示和允许编辑扩展名，应遵循 Explorer 当前的扩展名显示设置。

## 图标拖动

- 自动排列、拖动落位和旧位置恢复都限定在各显示器工作区内，避开常驻任务栏和显示器之间的不可见区域；底行长文件名展开后也不越过工作区。任务栏自动隐藏时遵循 Windows 返回的工作区。
- 拖动预览以鼠标位置为首个图标中心，最终落点与预览一致。
- 多选拖动保持各图标相对排列，桌面落位时整体平移；冲突项使用最近空网格。
- 拖动经过普通图标时不能改变拖动源或出现替换效果；只有有效文件夹或回收站显示投放提示。
- 桌面和收纳盒内部均按鼠标命中的实际槽位排序，被挤开的项目使用平滑回位动画。
- 系统虚拟图标可以在桌面层移动并保存位置，但不能进入收纳盒或提供真实文件拖放数据。

## 文件拖放

- 桌面文件拖入收纳盒只增加视觉归属，不移动真实文件。
- 收纳盒文件拖回桌面只解除视觉归属，不执行 Desktop 到 Desktop 的同名移动。
- 外部文件拖入时遵循 Windows 的同盘移动、跨盘复制和 `Ctrl` / `Shift` 修饰键语义。
- 真实文件可拖入桌面文件夹或回收站；资源管理器文件夹中的项目可拖回桌面或收纳盒。
- 投放事件只能由一个目标处理一次，不能产生额外的“(2)”副本。
- 从 MiniC 拖到浏览器、聊天工具或资源管理器时提供标准 Windows 文件拖放格式。

## 收纳盒

- 标题栏的非按钮区域用于移动收纳盒；标题单击拖动与双击改名不能互相误触发。
- 图标视图中的图标使用固定顶部基线，文件名显示一行或两行都不得改变同一行图标的垂直位置。
- 收纳盒可折叠、切换图标或列表预览，并独立保存颜色和透明度。
- 多个收纳盒可合并为标签组，标签宽度使用弹性布局并支持换序。
- 标签拖动开始时按主方向锁定手势：左右只调整标签顺序，即使越过盒子边缘也不拆出或合并；上下只用于抽离和合并，移回源标签栏不改变标签顺序。小幅抖动或方向不明确的斜拖暂不启动。
- 纵向拖动离开源标签栏时抽出等尺寸卡片，原盒保持原样式；近距离边缘通过柔性连接衔接，距离增加后连接拉细断开。未命中合并接收区时，释放后在预览位置拆出。
- 合并仅在鼠标命中目标标签栏时触发；目标为无标签栏的独立盒时使用顶部名称区域。文件内容区、标题栏按钮和盒子空白区域不接收合并，高亮只覆盖实际接收区；标签和整盒拖动共用此命中规则。
- 命中接收区只显示主题色细边框，不填充背景、不淡化标题或文件内容。释放后卡片沿接触方向滑入并通过遮罩融合，追加到目标标签末尾。
- 合并与拆分不缩放实际窗口、图标或文字；单标签预览不包含其他标签。预览与最终拆出使用相同 DIP 落点计算。
- 拖动预览复用原材质、标题和内容，保持原颜色、渐变和透明度；不添加浅色底板或提高背景不透明度。融合只裁剪形状，不额外淡化整张卡片。
- 持续拖动逐帧直接跟手，不反复启动追赶动画；透明度仅在状态切换时过渡。落地后不再追加内容位移，未参与拓扑变化的收纳盒保持原窗口；重复排版不打断正在进行的换位动画。
- 移回源盒或按 Escape 时卡片平滑归位；失去捕获、失活或窗口关闭时清理预览。动画关闭设置下快速完成过渡。
- 拖动未释放前只表达意图，不改变标签拓扑；取消或移回源位置应恢复原状态。

## Windows 集成

- 文件和系统图标右键使用 Windows Shell 的公开 `IContextMenu` 能力，包含已安装软件注册的扩展命令。
- Windows 11 现代右键菜单由 Explorer 内部宿主，第三方顶层窗口没有公开调用接口；项目不自绘冒充该菜单。
- 桌面空白右键使用 Windows Shell 桌面视图公开提供的背景 `IContextMenu`；菜单命令始终以 Desktop 为目标，不按隐藏 Explorer 图标坐标命中文件或文件夹。
- 桌面空白菜单保留系统当前提供的查看、排序、刷新、新建、显示设置、个性化及已注册扩展命令；系统应用扩展区域附加带 MiniC 应用图标的 `MiniC` 子菜单，仅提供新建收纳盒和显示或隐藏收纳盒。这些 MiniC 动作必须回到 `DesktopCoordinator`，不得由菜单服务直接修改布局。
- 从桌面空白菜单的系统“新建”子菜单创建任意已注册类型时，包括文件夹、文本文档、快捷方式及应用扩展文件，新增图标都以打开菜单时鼠标所在的 MiniC 网格为首选落点；该格已占用时从此处向外选择最近空格，之后再进入名称确认。
- 文件系统变化由 Windows Shell 桌面通知驱动，手动“刷新”才执行完整同步。
- 文件进入系统复制或剪切剪贴板后仍可正常选中，并显示与普通项目一致的选中背景和描边。复制和剪切使用相同蓝色、尺寸和底板的对称矢量标识；剪切只降低文件图标与名称透明度，状态标识保持清晰。桌面和收纳盒状态同步，剪贴板内容变化时立即更新或清除。
- 图标和图片缩略图使用等比例完整缩放，不拉伸、不裁切。
- MiniC 全屏桌面图标层始终处于普通应用下方、Explorer 桌面上方。收纳盒未激活时位于桌面层；用户点击后按 Windows 普通活动窗口规则进入前台，但不设置永久 Topmost，点击其他应用后立即退回桌面层。收纳盒始终位于 MiniC 桌面图标层上方。
