# 交互行为

[English](en/INTERACTIONS.md)

本文记录 MiniC 桌面层和收纳盒应保持的用户可见行为。实现细节改变时，这些结果仍应成立。

## 选择与编辑

- 双击以两次按下的系统时间与屏幕距离判定，在第二次有效松开时打开；拖动、未完成的点击、切换项目或点击空白区域会取消无效连续点击。
- 文件元数据刷新保留正在使用的图标对象、选择与编辑状态；重命名期间不隐藏整个桌面图标层，文件变化延后同步而不直接丢弃。
- 桌面和收纳盒项目按 Windows 双击时间与距离识别连续点击，不依赖桌面层激活前后的 WPF 点击计数；已进入拖动的手势不得触发打开。
- 单击选中一个图标时显示完整名称；取消选中或多选时恢复紧凑名称。
- 桌面和收纳盒空白区域支持框选，`Ctrl` 框选用于追加或反选。
- 点击其他桌面区域、收纳盒或普通应用时，清除不再有效的选择、菜单和编辑状态。
- `F2` 或重命名命令在名称位置原位编辑；默认只选中文件名主体，不选中可见扩展名。文件名失去焦点即提交，`Enter` 仍可提交，`Escape` 取消。点击其他位置、切换窗口或标签都不会丢弃未提交的文件名。
- 失焦提交完成后不抢回焦点；同一文件的重复失焦事件只提交一次。无效名称或重名仍由文件服务拒绝，原文件保持不变；失焦提交失败结束编辑并恢复原名称。
- 重命名编辑器只替换图标下方的原名称，宽度不得超出文件名槽位，也不得横向撑开图标项或遮挡图标；使用单行横向滚动，完整文件名不因换行而被网格裁切。
- 在重命名输入框内拖动选择文字时，鼠标事件只用于文本选择，不得移动文件图标。
- 双击收纳盒标题后在标题栏原位编辑；`Enter` 或失焦提交，`Escape` 取消。
- 静态文件名显示遵循 Explorer 当前设置；进入重命名后，普通文件始终显示完整名称并允许修改/删除扩展名，`.lnk` 与 `.url` 快捷方式隐藏并保留后缀。普通文件默认只选中主体；文件夹和隐藏后缀的快捷方式选中整个可编辑名称。
- 后台每秒校正当前收纳盒时保留标题/文件名编辑状态、输入草稿和选择，不把同一标签的重复配置当成用户切换标签。

## 图标拖动

- 收纳盒内部拖动时，原图标、文件名和选中背景暂不绘制，只保留布局占位，鼠标携带的预览是唯一可见副本。多选、图标视图和列表视图共用此规则；结束、取消或异常后恢复。
- 自动排列、拖动落位和旧位置恢复都限定在各显示器工作区内，避开常驻任务栏和显示器之间的不可见区域；底行长文件名展开后也不越过工作区。任务栏自动隐藏时遵循 Windows 返回的工作区。
- 拖动预览以鼠标位置为首个图标中心，最终落点与预览一致。
- 多选拖动保持各图标相对排列，桌面落位时整体平移；冲突项使用最近空网格。
- 拖动经过普通图标时不能改变拖动源或出现替换效果；只有有效文件夹或回收站显示投放提示。
- 桌面和收纳盒内部均按鼠标命中的实际槽位排序，被挤开的项目使用平滑回位动画。
- 系统虚拟图标可以在桌面层移动并保存位置，但不能进入收纳盒或提供真实文件拖放数据。

## 文件拖放

- 桌面文件拖入收纳盒只增加视觉归属，不移动真实文件。
- 收纳盒文件拖回桌面只解除视觉归属，不执行 Desktop 到 Desktop 的同名移动。
- 外部文件拖入时遵循 Windows 的同盘移动、跨盘复制和 `Ctrl` / `Shift` 修饰键语义。
- 真实文件可拖入桌面文件夹或回收站；资源管理器文件夹中的项目可拖回桌面或收纳盒。
- 投放事件只能由一个目标处理一次，不能产生额外的“(2)”副本。
- 从 MiniC 拖到浏览器、聊天工具或资源管理器时提供标准 Windows 文件拖放格式。

## 收纳盒

- 标题栏按钮独立处理鼠标按下；预览事件不把焦点抢到选择区、不触发标题拖动。菜单打开前即标记临时弹层状态，避免失活清理提前关闭颜色子菜单。
- 首次点击由窗口统一处理激活，包括标题、按钮及内容边缘；保留原点击事件，延迟清理/焦点恢复需匹配当前交互版本。标题与文件名按 Display/Grayscale 清晰绘制，并使用共享柔和下投影。三种材质默认采用 16 DIP 圆角，WPF 遮罩、玻璃边框和原生 Composition 后景共用实际外观半径，原生区域按 DPI 换算。标题栏和背景保留最低非零 alpha，防止高透明度下鼠标穿透；数量徽标使用独立高对比配色。
- 三种材质使用同一主题色板；晶透的可见色层加强，颜色切换不会重置材质、透明度或布局。在接近完全透明的档位，底色差异自然减弱。
- 收纳盒的白色标题、文件名、组件文字和图标统一带柔和深色下投影；白色桌面、浅色壁纸和近白色材质背景下保持可读，投影不贴边形成轮廓，不改变前景颜色，也不参与后景采样。
- 拆出预览固定采样各层的实际布局边界，视觉偏移仅应用一次；完整盒由原窗口立即交接到预览，避免两份标题同时淡入淡出。预览继承来源盒子的实际圆角（默认 16 DIP），预览和阴影按当前缩放比例计算。
- 重命名失败提示归属于发起操作的收纳盒或桌面图标层。Win32 模态提示禁用所属窗口期间，桌面层级服务不得重设其 Z 序或激活样式；Enter 提交失败后回到名称编辑器，失焦提交不主动抢回焦点。文件打开失败、解散收纳盒和删除组件的提示也指定发起窗口。
- 托盘右键主菜单与“新建组件”子菜单统一使用 WinForms 默认菜单样式及布局，不再保留单独的奶白色主菜单绘制器。
- 收纳盒和组件拖动共用 BoxSnapGeometry：与邻近可见宿主的同侧或相邻边缘距离不超过 6 DIP 时，独立吸附横纵坐标；正交方向距离超过 32 DIP 的盒子不参与吸附，物理屏幕坐标按拖动窗口 DPI 换算。每帧从原始抓取点计算，移出范围自然解除；中央合并目标优先，普通点击不启动拖动，松手先提交最终位置再保存布局。
- 右下角缩放热区为 32×32 DIP，透明 Border 覆盖整个区域；可见图案仍为 11×11 DIP，保持靠右下的位置，不扩大图案。最小展开尺寸仍为 250×170 DIP，折叠时隐藏缩放入口。
- 外观菜单的“透出后方窗口”使用固定文字与勾选状态，新建默认不勾选；“截屏录屏时显示窗口”默认勾选，内部继续使用反向的 HideFromCapture 字段，保存和重开菜单保持一致。已有盒子保留设置。
- 晶透预览保持壁纸层/着色器绘制尺寸不变，使用 RenderTransform 缩放，按变换后的屏幕范围采样；毛玻璃用单次 SetWindowPos 合并本帧位置和大小更新。所有模式共用一个渲染时钟，静止且比例收敛后停止重复渲染。
- “背景透明度”在单盒菜单和托盘中统一为 0–100%，数值越大底色越淡；毛玻璃仍保留背景模糊。文件内部继续保存 Opacity（不透明度），读取旧值不反转，界面显示为 1 − Opacity。原生 Acrylic 最透档仅保留 1/255 色调 alpha，避免零 alpha 的兼容问题；不调整文字/图标的不透明度。
- 新建收纳盒和组件使用同一空闲位置策略，优先在来源或已有可见宿主所在屏幕的工作区内避开已有宿主，保留 12 DIP 间距；没有可见宿主时使用主屏工作区。屏幕放满时选择重叠最少的位置，不反复叠放在同一坐标。
- 合并接收高亮使用不参与测量的叠加层，不能改变目标窗口、标签栏或内容区的布局尺寸。命中依据原始布局的物理屏幕坐标，不随来源窗口的视觉缩放缩小。
- 外观只保留“晶透、毛玻璃、纯色”。晶透关闭透出时折射桌面壁纸，开启透出时折射按 Z 序捕获的后方窗口；两种模式共用中心保真、边缘折射和双对比边框。捕获不到窗口时回退壁纸晶透。纯色沿用之前清透的半透明底色与柔和光泽。
- 旧 Clear、Satin、Gradient 和未知材质映射到 Solid（新纯色）；Crystal、Frosted 保留。单盒菜单和托盘统一设置共用这三个选项，新建与保存也只使用规范值。
- 晶透读取 IDesktopWallpaper 的每屏图片及壁纸布局，后台解码缓存，移动时只更新采样坐标；设置/显示变化时刷新。拖动预览分别绘制实时壁纸折射与前景快照，不把旧位置的壁纸冻结在卡片里。图标和文字不参与着色器处理。
- 毛玻璃默认使用收纳盒内部的圆角底色、纹理和可调模糊层，不采样桌面壁纸；打开“透出后方窗口”后才启用窗口级背景模糊。图标和文字不参与模糊，圆角由同一内容 Clip 控制；切换材质/标签时清理旧 Native Acrylic 状态，避免矩形阴影残留。
- 普通预览继续使用稳定的大画布；原生毛玻璃预览的 HWND 逐帧贴合卡片大小，因为原生模糊不遵守 WPF 内部裁剪。返回源栏时同步停用隐藏预览的模糊，完整拖动隐藏原盒绘制与模糊，取消/落地恢复；不做屏幕截图采集。
- 纵向拆出时，预览显示前就设为小尺寸并位于鼠标抓取点，离源标签栏越远越大；返回源栏则逐渐变小并淡出。源/目标标签距离共同决定比例；位置与缩放锚点同帧提交，避免首帧闪大及回拖跳位。
- 标题栏的非按钮区域用于移动收纳盒；标题单击拖动与双击改名不能互相误触发。
- 图标视图中的图标使用固定顶部基线，文件名显示一行或两行都不得改变同一行图标的垂直位置。
- 收纳盒可折叠、切换图标或列表预览，并独立保存颜色和透明度。
- 任意收纳盒都可作为来源向指定目标合并，不依赖创建顺序或宿主列表顺序。整盒拖动将来源的全部标签追加到目标末尾，保留目标的身份、位置、尺寸、折叠状态和外观，并激活拖动的来源标签；标签拖动只转移所拖标签。
- 标签拖动开始时按主方向锁定手势：左右只调整标签顺序，即使越过盒子边缘也不拆出或合并；上下只用于抽离和合并，移回源标签栏不改变标签顺序。小幅抖动或方向不明确的斜拖暂不启动。
- 纵向拖动离开源标签栏时抽出等尺寸卡片，原盒保持原样式；近距离边缘通过柔性连接衔接，距离增加后连接拉细断开。未命中合并接收区时，释放后在预览位置拆出。
- 标签拖动使用目标中央 60% 宽高的接收区；整盒窗口拖动使用目标完整范围。目标按实际窗口 Z 序选择，跳过来源整个宿主；指针落在上层目标边缘时，不能穿透合并进其后方盒子。
- 整盒指针在同一目标范围稳定停留 0.2 秒，标签指针仍按中央接收区计时；期间移动超过 10 DIP 或切换目标重新计时。准备后显示无边框的“松开以合并”提示，松手必须仍命中已显示提示的同一目标，松手本身不补触发合并。起始已命中的重叠目标需先离开再进入，避免把移开重叠盒子的操作当成合并。
- 整盒移动和背景对齐按渲染帧合并，每帧只提交最新指针位置；合并缩放以鼠标抓取点为锚，由单一渲染帧状态机驱动，目标进出不重启相互冲突的动画。
- 准备合并后来源平滑缩至约 38%，离开目标后恢复；仅改变视觉缩放，实际窗口及保存尺寸不变。
- 盒内图标排序以未受动画变换影响的布局格子命中，在格子边缘保留缓冲，避免让位动画反过来触发来回排序；布局失效后保留旧视觉位置，换位从当前显示位置连续衔接。
- 拖动预览复用原材质、标题和内容，保持原颜色、渐变和透明度；不添加浅色底板或提高背景不透明度。融合只裁剪形状，不额外淡化整张卡片。
- 持续拖动逐帧直接跟手，不反复启动追赶动画；透明度仅在状态切换时过渡。落地后不再追加内容位移，未参与拓扑变化的收纳盒保持原窗口；重复排版不打断正在进行的换位动画。
- 普通整盒移动在松手时保存落点；路过或离开合并区、失去捕获都不回弹。Escape 明确取消整盒移动并回到拖动起点；标签移回源盒取消转移。结束、取消、失活或窗口关闭清理预览与合并计时器。动画关闭时立即完成过渡。
- 拖动未释放前只表达意图，不改变标签拓扑；取消或移回源位置应恢复原状态。

## Windows 集成

- 文件和系统图标右键使用 Windows Shell 的公开 `IContextMenu` 能力，包含已安装软件注册的扩展命令。
- Windows 11 现代右键菜单由 Explorer 内部宿主，第三方顶层窗口没有公开调用接口；项目不自绘冒充该菜单。
- 桌面空白右键使用 Windows Shell 桌面视图公开提供的背景 `IContextMenu`；菜单命令始终以 Desktop 为目标，不按隐藏 Explorer 图标坐标命中文件或文件夹。
- 桌面空白菜单中的查看、排序方式、分组依据、自动排列和对齐到网格由 MiniC 自己生成并保存 `NativeDesktopState`，点击后直接重排自绘图标层；原生 Explorer 的刷新命令被移除，换成 MiniC 刷新命令，避免只刷新被隐藏的 `SysListView32`。显示设置、个性化、系统新建和已注册扩展仍交给 Shell。
- 桌面菜单的系统应用扩展区域附加带 MiniC 应用图标的 `MiniC` 子菜单，从与托盘共用的 `BoxCreationCatalog` 生成新建收纳盒、天气、日程中心入口，并保留显示或隐藏收纳盒。新增支持的类型统一维护此目录，菜单打开时按目录生成；这些 MiniC 动作必须回到 `DesktopCoordinator`，不得由菜单服务直接修改布局。
- 收纳盒空白区域也显示 Shell 背景菜单，但不显示会改变桌面排序的查看/排序/分组项；其中的刷新、新建和粘贴由协调器处理，新建或粘贴产生的真实 Desktop 项目会自动写入当前收纳盒的视觉归属并刷新内容。
- Windows 11 现代右键菜单由 Explorer 内部宿主，第三方顶层窗口没有公开直接调用接口；项目使用公开的 `IContextMenu` 和 Win32 菜单承载原生文件命令，并记录构建、查询和执行失败到 MiniC 本地日志。
- 从桌面空白菜单的系统“新建”子菜单创建任意已注册类型时，包括文件夹、文本文档、快捷方式及应用扩展文件，新增图标都以打开菜单时鼠标所在的 MiniC 网格为首选落点；该格已占用时从此处向外选择最近空格，之后再进入名称确认。
- Shell 通知与真实桌面目录的 FileSystemWatcher 并行监听创建、删除、改名、写入、大小和属性变化；外部程序无需主动调用 Shell 通知即可更新桌面。
- 每秒在后台比较桌面直接子项目的路径和元数据，差异出现时才进入列表同步；通知或刷新忙碌期间的请求合并保留，不每秒重建图标和窗口。重命名及菜单操作期间延后处理，外部改名在刷新锁内应用。
- 回收站计数独立查询并更新系统空/满图标，不经通用虚拟图标缓存；查询/图标获取失败保留上一有效状态并重试，退出后丢弃迟到结果。
- 文件进入系统复制或剪切剪贴板后仍可正常选中，并显示与普通项目一致的选中背景和描边。复制和剪切使用相同蓝色、尺寸和底板的对称矢量标识；剪切只降低文件图标与名称透明度，状态标识保持清晰。桌面和收纳盒状态同步，剪贴板内容变化时立即更新或清除。
- 图标和图片缩略图使用等比例完整缩放，不拉伸、不裁切。
- MiniC 全屏桌面图标层始终处于普通应用下方、Explorer 桌面上方。收纳盒未激活时位于桌面层；用户点击后按 Windows 普通活动窗口规则进入前台，但不设置永久 Topmost，点击其他应用后立即退回桌面层。收纳盒始终位于 MiniC 桌面图标层上方。
- 点击收纳盒标题栏空白、名称、操作按钮及标签，与点击内部内容一样激活到前台；开始拖动前保留按下手势坐标，标题双击仍用于重命名。
