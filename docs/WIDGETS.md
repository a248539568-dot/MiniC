# 桌面组件实施规划（2026-09-20）

2026-09-24 接手调整：组件和收纳盒继承同一个 `DesktopBoxWindow` 窗口外壳，统一基础窗口属性、点击激活与桌面层归位；内容、拖放和存储仍保持各自职责。附件路径在打开与删除前校验目录/文件名，拒绝越界路径。

2026-10-18 日程中心：在同一宿主提供“概览 / 专注 / 日历 / 日程 / 待办”五个中文页面。概览显示实时时间及全部未完成待办、日程，按事项时间倒序，无时间事项放最后；专注页提供 15/25/45/60 分钟倒计时、开始/重置；日历仅展示月历，点击日期进入日程页的当天列表及黄历；日程页也可查看全部日程，待办页管理完成状态并可编辑，暂不提供搜索。事项在 `entries.entry_kind` 中保存为 `Task` 或 `Schedule`，旧数据库启动时自动补列。新建和编辑使用一个多行输入框，日期时间入口浮在框内；输入框、时间下拉、复选框、日期选择面板使用统一的自定义样式和模板，编辑错误在表单内提示。天气小盒子按当前天气、未来小时和未来几日自适应重排，仍由原有天气服务提供数据。五页、天气与原有组件共用收纳盒宿主、材质和透明度。所有新建收纳盒和组件统一由第一个有效盒子宿主提供尺寸，没有有效宿主时使用 340×380 基准；天气菜单主动切换大窗仍保留。

## 产品边界

组件盒子与文件收纳盒并列存在：共用主题、晶透/毛玻璃/纯色材质、圆角，并通过同一桌面窗口层服务共用首次点击激活和相对层级规则；点击外壳、标题栏、正文或按钮区域都会在同一次按下中激活窗口。组件内容不进入桌面文件夹，也不参与文件收纳盒的拖入/拆分手势。托盘的新建入口只创建日程中心或天气；备忘录、待办、日程、日历旧组件仍可读取和操作已有数据。标题栏移动，右下角缩放，当前盒子菜单切换材质和重命名；隐藏后可在托盘恢复，删除需确认。

## 已实现的第一阶段

- **备忘录**：Markdown 源码编辑、预览（标题、强调、行内代码、列表、引用、HTTPS 链接和已导入图片）、失焦前 450 ms 自动保存、单条提醒。
- **待办**：紧凑列表按进行中/已完成分组，顶部输入名称可按回车或按钮快速添加；单击圆圈切换完成状态，单击条目展开名称、说明、截止时间与提前提醒编辑，并可导入附件或删除。
- **日程**：新增、编辑和删除带时间的事项，默认提前 10 分钟提醒；可为选中日程导入附件。
- **日历**：月视图、月份切换、日期筛选，显示待办与日程的日期标记、农历、节日与节气；日期详情显示民俗黄历及可用天气，并可新建或编辑待办、日程。
- **天气**：窗口延续收纳盒材质和圆角，标题栏只保留同款三点菜单；小窗按“城市/当前温度/天气状态、未来小时、未来几日”紧凑排版，大窗保留更宽的小时预报。菜单可切换大窗/小窗，模式和尺寸写入 SQLite，重启后保留；旧数据库会自动补充 `view_mode` 字段。菜单内还可改城市、重新定位、刷新、切换材质、重命名、折叠和隐藏。首次打开通过 IP 粗定位估计城市，手动城市会覆盖估计结果；同一城市缓存 30 分钟。国内城市优先使用中国气象局 weather.cma.cn 的站点实况、每日与三小时预报；请求或解析失败时依次回退 wttr.in、Open-Meteo，三个来源均无需用户填写 Key。七种天气状态使用项目内 SVG 矢量图标。
- **日程中心**：通过托盘“新建组件 -> 日程中心”创建。五页共用底部浮动导航，不显示重复刷新栏；待办、日程页通过无边框、无填充的粗加号矢量图标新建。列表复用左侧色条、正文和右侧时间的布局；概览合并所有未完成事项，按 `DueUtc` 倒序，无时间事项放最后。概览和日程条目打开只读阅读面板，通过上下箭头或 PageUp/PageDown 翻阅；可进入编辑，返回原列表保留筛选和滚动位置。待办点击进入编辑，时间变更可恢复已完成事项。新建和编辑只有一个多行输入区，无独立标题字段，第一行作为摘要、其余为正文，已有内容完整回填；时间入口浮在输入框底部，使用共用的自定义日期、小时分钟选择器。待办时间可留空，日程必须选时间，从日期页新建沿用选定日期，从全部日程新建使用今天。仅修改文字保留原时间精度。输入区随宿主伸缩、长文内部滚动，五页切换不改变窗口、材质或位置。
- **附件**：备忘录、待办和日程支持多选导入图片/文件，复制到 `%LOCALAPPDATA%\MiniC\WidgetAttachments`；图片在备忘录中插入 `attachment://` 引用并可预览。删除附件、条目和组件时清理对应文件。
- **提醒**：MiniC 运行时每 30 秒检查一次，启动时补报过期提醒；通过 Windows 托盘通知展示，点击通知打开对应组件。使用 UTC 入库，输入/显示均为本地时间。

## 日程中心列表交互

日程中心概览与待办列表由 `WidgetContentView.PlannerRows` 共用行行为，`PlannerEntryStatus` 提供右侧固定 64×36 DIP 的时间区域及 28 DIP 圆形完成控件；二者均垂直居中，悬停或键盘焦点进入时用 120 ms 淡入淡出替换，不改变布局。当天显示时分，跨日增加日期，无时间显示“未设时间”。点击正文仍按所在页面进入阅读或编辑，完成按钮独立处理点击。

完成操作读取最新条目后立即保存状态，不覆盖其间修改的正文或时间；随后用 180 ms 向右移出和淡出，100 ms 后开始 160 ms 行高收拢。动画结束原位移除条目并更新数量/空状态，不重建剩余行。重复点击被阻止，动画只操作仍属于当前列表的行，切页、编辑或停止组件后不会覆盖新页面。系统关闭界面动画时直接更新结果。

待办筛选只保留“待办 / 完成”，删除“更新”入口及查询分支。切换栏在正文中水平居中，最大宽度 240 DIP，窄窗随可用宽度收缩。完成项以删除线展示，点击正文进入编辑；改变日期、时分或清除时间并保存后恢复为待办，回到待办列表，仅修改正文不恢复。

完成行使用 `PlannerCompletedEntryActions`，不再提供恢复按钮；悬停或键盘聚焦时在时间区域显示删除、勾选两个操作。勾选只记录待删除选择，不改变完成状态，移出后保留选择指示。完成页顶部提供“删除勾选项”和“清空已完成待办”，通过页面内自定义确认区执行，可取消；只删除确认时仍属于当前盒子且已经完成的待办及其附件，不删除未完成事项、日程或其他盒子的条目。切页后的旧确认无效，删除后复用行移出动画。

## 月历与日程页

月历下方不再内联显示所选日期、“新建日程”和“当天安排”。日期格显示公历日、农历或节日/节气、已公布的中国休/班标记以及未完成事项圆点；空间不足的节日名称省略，悬停显示完整日期、节日分类及事项数量。点击日期设置当天筛选并切换“日程”页，该页按时间升序显示当前盒子的未完成待办和日程，不混入其他盒子、已完成事项或无时间待办。支持前一天、后一天、今天、返回原月份和全部日程；全部日程只列未完成日程。完成后沿用原位滑出动画，更新日程空状态。

当天页显示完整农历日期、节日/节气及官方放假信息；黄历可展开查看干支、宜、忌，淡入淡出切换，系统关闭动画时直接切换，仅作民俗参考。日程页共用阅读、翻页、编辑和时间选择器，不增加第二套事项存储。底部五个页签在 234 DIP 宽度下仍保持可用。

节气与黄历来自 lunar-csharp 1.6.8，中国调休沿用明确发布的 2026 年安排，其他年份不推算放假。常见国际纪念日依据 [联合国国际日和国际周官方日历](https://www.un.org/en/observances/list-days-weeks) 核对，当前收录世界湿地日、国际妇女节、世界水日、世界气象日、世界卫生日、世界地球日、世界读书日、国际家庭日、世界环境日、世界海洋日、国际扫盲日、国际和平日、世界粮食日、联合国日、世界艾滋病日和世界人权日；与中国休假字段分开保存。国际纪念日不代表全球法定休假，当前没有逐国法定节假日日历。

## 数据设计

`%LOCALAPPDATA%\MiniC\widgets.db` 是独立 SQLite 数据库，启用 WAL 和外键。`widgets` 保存组件位置、尺寸、显示模式、材质、文本与城市；`entries` 保存待办/日程及 `entry_kind` 类型；`attachments` 只保存随机文件名、原始文件名和所属关系。旧库启动时通过 `Ensure` 为 `entries` 增加 `entry_kind`，原有待办和日程数据不丢失；旧 `Schedule` 组件仍按组件类型识别日程。所有 SQL 均参数化，附件实际目录和文件名校验后访问。原有 `layout.json` 不迁移、不混入大段备忘录内容。删除组件使用外键级联清理条目和附件索引。

## 验证

组件验证采用不显示窗口的单元测试，覆盖 SQLite 重启持久化、附件级联、提醒去重、天气解析和请求取消。真实窗口激活与菜单交互需在单独的测试会话人工验收，不再运行会抢占用户鼠标或弹出盒子的脚本。

## 天气数据与隐私

天气查询不保存第三方 API Key。MiniC 先按城市名称匹配中国气象局 weather.cma.cn 站点，读取站点实况、七日预报和三小时预报；接口失败或城市未匹配时，按经纬度访问 wttr.in 的 `format=j1` JSON，再失败则回退 Open-Meteo。wttr.in 返回本地化文本时优先显示中文，否则按天气代码和英文描述转换为中文天气类别。结果按城市缓存 30 分钟，气象局观测更新时间与本地缓存写入时间分别管理，界面会显示本次实际使用的数据源。

首次定位通过同一个明确启用系统代理的 HTTPS 客户端访问 ipwho.is，它会接收代理出口的公网 IP 并估计城市及坐标；再用同一代理路线访问 Open-Meteo 地理编码本地化城市名称。IP 定位只提供城市级近似位置，代理/VPN 会影响结果。手动城市优先，不会在已有城市时自动改写。天气查询需要互联网；无法定位时可自行输入城市。
