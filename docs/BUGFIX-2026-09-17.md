# 外部保存、回收站状态与标题栏激活修复

日期：2026-09-17。基于 0.58.9，纳入 0.59.0。本次发布同时包含桌面及收纳盒文件失焦重命名。

## 原因和修复

1. 原来 Shell 注册成功后不启动 FileSystemWatcher，仅订阅 ShellLevel 通知。直接写文件的应用可能没有对应 Shell 通知；忙碌时刷新请求也会被丢弃。现在并行监听真实桌面目录，每秒后台比较轻量元数据快照，存在差异才同步列表；刷新请求合并保留，快照仅在完成刷新后提交。
2. 回收站只在文件列表刷新时查询计数，且普通虚拟图标加载可能晚于空/满图标完成并覆盖结果。现在订阅回收站 Shell 命名空间，并每秒独立查询真实计数；通用图标加载排除回收站，专用服务串行更新系统图标，失败重试、退出丢弃迟到结果。
3. 内部内容点击调用激活入口，标题栏拖动和标签点击没有调用。现在标题栏空白、名称、按钮和标签都明确激活窗口，并在启动拖动前保存手势坐标；仍遵循普通前台窗口规则，不设置永久 Topmost。

文件监听批次同时包含改名和其他文件变化时，不因过滤已知内部改名而丢弃其他变化。外部改名统一排队，在刷新锁内应用，避免后台枚举归属字典时修改集合；打开背景菜单也保留未处理的改名。

## 验证

- Release 构建零警告、零错误；49/49 独立测试通过。
- 新增共享文件名提交会话和两类编辑器的失焦自检：真实临时文件在失焦后改名、Escape 不改名、无效名称不修改原文件，异步提交不抢回焦点。
- 隔离目录直接写临时文件并改名为图片文件，不调用 SHChangeNotify，验证仍收到真实文件监听事件。
- 快照覆盖新增、改名、删除、相同修改时间但大小变化，以及差异检查不提前消费基线。
- 回收站覆盖有内容→清空→重新有内容、查询失败、图标获取失败重试、替换模型、重叠查询和退出后的迟到结果。
- 收纳盒自检用独立竞争窗口先令测试盒失活，再向标题栏、名称、菜单按钮和标签发出 WPF 路由按下/松开事件，验证激活且几何和手势状态正常。
- 收纳盒组织、重命名、启动专项自检通过；截图为 `.local/validation/20260917/header-activation.png`。

没有操作用户真实桌面文件或清空实际回收站，也没有声称在 Photoshop 内完成端到端操作。实际 Photoshop 保存、多屏前台切换及安装升级仍需现场复核。0.59.0 的打包和远端发布结果见 development.log。
