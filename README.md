# MiniC — Windows 桌面整理与图标收纳工具

[English](README.en.md)

MiniC 是一款面向 Windows 11 的桌面整理软件（Windows desktop organizer），支持桌面图标分组、桌面收纳盒和标签式管理。它用独立桌面图标层和可组合的收纳盒整理快捷方式、文件与文件夹，同时让真实文件继续留在用户桌面或公共桌面中。

> 本地构建版本：`0.60.83`。面向 Windows 11，x64。许可证状态见文末。

本地 0.60.83 完整替换标签拖出预览动画：预览首帧直接使用最终尺寸，位置、抓取锚点和缩放值在同一渲染帧提交，不再使用旧的缩放追赶动画或动态改变卡片尺寸；整盒合并拖出仍使用抓取点锚定的单一渲染帧缩放状态机。

本地 0.60.80 调整收纳盒窗口合并：任意收纳盒均可拖向目标盒子完整范围合并，不依赖创建或列表顺序，重叠目标按实际窗口层级选择。鼠标在目标范围稳定停留 0.2 秒，出现“松开以合并”动画后释放才合并；开始拖动时已经命中的重叠目标需要先离开再进入。路过或离开合并区后松手保留移动位置，Escape 才取消并回到起点。新建收纳盒和组件优先选择当前屏幕工作区的空闲位置，空间不足时选择重叠最少的位置。

本地 0.60.77 修复收纳盒标题和文件图标重命名时被后台校正提前结束编辑的问题，重复校正当前标签不再提交草稿或清除选择。桌面和收纳盒的普通文件重命名始终显示完整文件名，可修改或删除扩展名；默认只选中文件名主体，`.lnk` 与 `.url` 快捷方式隐藏并保留后缀。输入框单行横向滚动，避免完整文件名换行后被固定网格裁切；改名后的图标重新读取。

本地 0.60.76 包含后台性能修复：实时折射盒子被普通不透明窗口完全盖住，或自身隐藏、最小化时暂停后景捕获与呈现，重新露出后刷新；逐窗口捕获由新帧事件唤醒，窗口层级静止时每 100 ms 检查一次，拖动时加快检查。完全遮住采样区的近处后景不再同时采集更深层窗口，保留材质和折射参数。实际 VMware 帧率尚未现场测量。

桌面空白右键菜单中的“查看”“排序方式”“分组依据”“自动排列”和“对齐到网格”由 MiniC 接管并持久化，固定网格上的图标顺序和位置会立即更新；“刷新”也改为刷新 MiniC 自己的桌面层，避免命中被隐藏的 Explorer 图标列表。收纳盒空白区域沿用 Windows Shell 的文件菜单，新建和粘贴完成后自动归入当前收纳盒。Windows 11 的现代右键菜单由 Explorer 内部宿主，系统没有公开的第三方直接调用接口，因此项目继续使用公开的 Shell `IContextMenu` 能力。

收纳盒文字和图标保持白色前景，同时使用统一的柔和深色下投影；投影覆盖白色桌面、浅色壁纸和近白色玻璃背景，避免内容消失，又不会贴边形成生硬轮廓，不改变图标本身的颜色。

收纳盒内容区使用统一的对称间距和水平/垂直居中策略，图标与文字区域使用深色半透明玻璃层和柔和阴影，窗口放大或缩小时保持内容位置稳定；列表模式保留紧凑布局。

日程编辑输入区单独使用居中且受限宽度的自适应布局，收纳盒缩放时保持中线不变；普通图标区从内容区左上角开始，按固定 82×88 DIP 单元和固定间距排列，网格不设置常驻背景填充，也不随图标原有尺寸改变。

组件内容容器在宽窗时保持整体居中，专注页、日程阅读详情和空状态保持居中；待办/日程列表、日历网格、天气预报和普通图标网格继续铺满或左起，以维持信息对齐。

本地 0.60.75 包含：概览与待办的右侧时间垂直居中，悬停切换为完成控件，完成后平滑移出和收拢。待办筛选只保留居中的“待办 / 完成”，窄窗自适应、宽窗限宽；完成项以删除线展示，悬停提供删除和多选，支持页面内确认清空或删除勾选项。编辑已完成事项时，仅修改正文保持完成状态，更改时间并保存后恢复待办。日历移除下方内联详情，点击日期进入新增的“日程”页，查看当天安排、农历及可展开的黄历；支持查看全部日程、阅读、编辑和新建。月历显示中国节日、节气、放假调休及常见国际纪念日，底部五页导航保持悬浮。246 项 Release 无可见窗口回归通过，已检查多尺寸离屏图。

本地 0.60.74 将文字与图标的黑白反差描边替换为共用的柔和下投影，保留玻璃窗口边框；删除旧前景描边着色器及构建引用，已检查明暗背景离屏图。

桌面右键的 MiniC 子菜单从与托盘共用的盒子类型目录生成“新建收纳盒 / 新建天气 / 新建日程中心”，以后新增类型只需维护同一目录；保留显示或隐藏入口及系统文件新建菜单。以上修改已包含在本地 0.60.74 安装包中，233 项 Release 无可见窗口回归通过，包含原生菜单结构和创建命令映射检查。

本地 0.60.73 包含统一 16 DIP 圆角、重命名提示层级修复、统一托盘菜单，以及 6 DIP 横纵边缘磁性对齐；右下角缩放热区扩大到 32×32 DIP，图案保持原尺寸。新建盒子默认不透出后方窗口、允许截屏录屏显示，菜单统一为固定文字的勾选项。

日程中心概览合并显示未完成待办与日程，按时间从新到旧排列，无时间事项放最后，不显示数量；点击进入阅读面板，支持上一条/下一条及 PageUp/PageDown，返回保留列表位置。待办新建使用无边框、无填充的粗加号矢量图标；新建和编辑共用一个多行输入框，时间入口悬浮在框内。以上修改已包含在本地 0.60.73 安装包中。

“透出后方窗口”适用于折射玻璃和液态玻璃，共用一个来源设置；切换材质不会重置玻璃的来源、折射、模糊、主题色、圆角与各自透明度。纯色不支持透明和后景采样。每个盒子和组件通过自己的菜单管理外观。

开启透出时，折射玻璃通过 Direct3D 11 整窗水纹折射 shader → Composition 交换链处理后景。所有折射玻璃都隐藏于截图时共享 DXGI Desktop Duplication；有折射玻璃允许截图时，统一切换到后方窗口的 Windows Graphics Capture GPU 纹理，按层级合成并排除 MiniC 自身，避免文字和边框反复被折射。液态玻璃保留系统后景画刷和高斯模糊。关闭透出时只绘制缓存桌面壁纸，折射玻璃执行相同配方的水纹与边缘折射，液态玻璃执行背景模糊。纯色始终是不透明的主题色。拆出预览复用各自材质规则和捕获开关，图标、文字、主题薄色与边框保持独立。

**捕获设置：** “截屏录屏时显示窗口”默认勾选，取消勾选后隐藏当前宿主及预览，覆盖三种材质和两种来源；前景标志由窗口管理，原生背景只管理自己的标志。切换不重建晶透或毛玻璃宿主；开启显示时等安全后景首帧提交，再恢复正常可捕获，不关闭折射。已有盒子保留自己的捕获设置。逐窗口捕获首次会申请系统无边框捕获许可；未获许可时 Windows 保留捕获提示边框。窗口首帧或尺寸尚未就绪时暂留上一张有效画面，已确认无法采集的窗口区域保持直透，不用更深层窗口、壁纸或黑色底板伪装。受保护画面仍受系统限制。

实时晶透在 GPU 内复制捕获纹理，同一显卡上的窗口会话按 HWND 共享，未再被采样时释放；壁纸只在改变时解码并上传。拖动使用同一位置快照绘制折射，再在同一次 UI 回调中批量移动前景/背景窗口并提交画面；快速鼠标输入合并到最新目标，结束或取消后拒绝旧移动。交换链最多一帧在途，按 DXGI 就绪信号调度；没有实测桌面 FPS。DXGI 路径同显卡多输出分区绘制，跨显卡同时覆盖时仅主区域折射；逐窗口路径在选定显卡上合成。桌面专用来源仍是静态壁纸，不包括桌面图标或动态壁纸。详见 [晶透材质](docs/CRYSTAL-WALLPAPER.md) 和 [毛玻璃材质](docs/FROSTED-GLASS.md)。

实现依据见[窗口层折射调研](docs/GLASS-WINDOW-RESEARCH-2026-10-14.md)。离屏 GPU 像素、旋转输出坐标、隐藏 HWND 交换链互操作、实际 DXGI 会话共享及资源释放已验证；没有运行可见桌面测试。

## 适用场景

- 桌面图标太多：把工作文档、常用软件快捷方式和项目文件分组放入不同收纳盒。
- 希望节省桌面空间：将多个收纳盒合并为标签组，左右排序，上下拖动拆出或合并。
- 希望保留熟悉的文件操作：继续使用 Windows 右键菜单、复制粘贴、重命名和拖放，桌面已有文件不因视觉分组而迁入私有目录。

## 为什么这样设计

- 文件仍是普通 Desktop 文件，上传、选择和资源管理器访问路径不变。
- 收纳只改变视觉归属，不把文件迁入私有目录。
- 每个独立收纳盒或标签组使用自己的顶层窗口，不覆盖整个桌面。
- 主程序异常退出后，守护进程恢复 Explorer 原生桌面图标层。

## 主要能力

- 桌面与收纳盒图标的选择、框选、拖动、排序和原位重命名
- 收纳盒合并为标签组、标签换序与拆出、折叠及列表预览
- 收纳盒与组件共用盒子宿主，类型化标签保留各自内容。材质、主题色和透明度分别管理；晶透关闭透出时折射壁纸，开启透出时使用原生 GPU 后景折射，文字和控件保持独立前景
- 任意收纳盒可向目标盒中央投放区合并，稳定停留约 450 ms 后显示“松开以合并”；来源整组标签追加到目标末尾并保留目标位置、尺寸及外观。普通移动、路过合并区或失去捕获都保留当前位置，Escape 取消移动。新建盒子优先避开已有宿主；屏幕放满时选择重叠最少的位置。标签纵向离开标签栏可拆出，拆出窗口沿用预览落点；动效不改变保存尺寸
- 壁纸变化时统一刷新可见盒子及组件的壁纸材质；托盘“刷新”也会重取纹理。读取失败时暂留上一画面，等待下一次通知或手动刷新
- 日程中心在同一个小盒子提供“概览 / 专注 / 日历 / 日程 / 待办”五页：概览合并列出未完成待办和日程，按时间倒序，无时间事项放最后，点击进入可上下翻阅的阅读面板；专注提供 15/25/45/60 分钟倒计时。日历仅展示月历，点击日期进入当天列表，按时间顺序显示同盒未完成待办和日程，提供农历、节日及可展开黄历；“全部日程”按时间顺序展示跨日期的未完成日程。待办管理完成状态。底部 Tab 保持悬浮；待办、日程页用无边框、无填充的粗加号图标新建，列表复用左侧色条、正文、右侧时间布局。新建和编辑只有一个多行输入框，时间入口浮在框内底部；输入、选择器、日期面板和滚动条使用统一自定义模板，校验提示显示在表单内。待办暂不提供搜索；时间通过日期和小时分钟列表选择，不要求手写时间。
- 日程中心支持随盒子尺寸自适应：窄窗自动将摘要、日期操作、任务时间和编辑页时间选择重排为上下布局；宽窗限制正文、专注区及悬浮 Tab 的最大宽度。字体不随窗口拉伸，缩放不重建页面，保留草稿和计时状态；高度不足时正文滚动，底部 Tab 固定悬浮，滚动条预留空间以避免布局抖动。
- 日期与时间选择器内部也随宽度伸缩：日期按钮与时分下拉等高，左右边界与表单对齐；窄窗日期独占一行，时分在下一行等宽铺满，日期弹层跟随可用宽度。
- 独立待办和日程组件仍可使用；待办按逾期、今日、稍后和已完成分组，日历按日期汇总两者并可编辑。
- 天气组件按盒子实际宽度自适应：当前天气横纵重排，小时预报自动换行，逐日预报在窄窗将温度移到描述下方；长城市名和天气描述可换行。宽窗正文限宽、高度不足时滚动，预留滚动条空间；缩放不重建内容或重新请求天气。
- 每个收纳盒独立颜色和透明度；新建收纳盒和组件统一使用第一个有效盒子宿主的尺寸，没有已有盒子时使用 340×380 的小盒子基准尺寸
- Windows Shell 文件右键菜单、文件夹投放和回收站投放
- 复制项目显示蓝色双页标识，剪切项目显示半透明剪刀标识，并随系统剪贴板同步
- 新增桌面文件增量落位，不打乱已有图标位置
- 文件扩展名、图片缩略图和拖放语义尽量遵循 Windows 设置与行为

## 快速开始

开发环境需要 Windows 11 和 .NET 10 SDK。克隆源码后，使用已安装的 SDK 执行：

```powershell
dotnet restore .\MiniC.sln --configfile .\NuGet.Publish.Config
dotnet build .\MiniC.sln -c Release --no-restore
```

本机若保留 `.dotnet` SDK，可将 `dotnet` 替换为 `.\.dotnet\dotnet.exe`；SDK、构建缓存和安装包均不提交到源码仓库。构建、运行和调试说明见 [开发指南](docs/DEVELOPMENT.md)。

## 项目结构

```text
src/MiniC/
  Controllers/   桌面与收纳盒业务协调
  Controls/      选择、布局和动画控件
  Models/        布局持久化模型
  Services/      文件、Shell、Explorer 和系统能力
  ViewModels/    可绑定的界面状态
  Views/         桌面层、收纳盒和托盘界面
installer/       Inno Setup 安装脚本
docs/            架构、开发、测试和维护文档
```

`DesktopCoordinator` 是唯一业务协调器。真实文件位置、视觉归属和窗口拓扑之间的关系见 [架构说明](docs/ARCHITECTURE.md)。

收纳盒与组件统一通过 `BoxHostState`、`BoxTabRef` 和 `BoxTopologyService` 管理宿主及标签，运行窗口共用一套拖动、合并、拆出和取消逻辑。旧的纯收纳盒拖放分支、专用回调和未使用自检已移除；`TabGroupId`、`TabOrder` 及其同步仍保留，用于旧布局迁移和数据一致性。无界面回归验证使用 `tests/MiniC.Tests`。

## 数据安全

- 布局保存在 `%LOCALAPPDATA%\MiniC\layout.json`，不保存文件内容。
- 配置写入采用临时文件替换，降低异常中断导致的损坏风险。
- 旧版本私有收纳目录会迁回桌面；同名时生成不冲突名称，不覆盖现有文件。
- 正常退出、异常退出和卸载流程都应恢复 Explorer 原生桌面。

操作布局文件前请先阅读 [数据与恢复](docs/DATA-SAFETY.md)。
